# kpax search implementation plan

**goal:** personal windows program launcher with edithub typography, two frosted themes and fast local search.

**architecture:** tauri 2 resident window; windows StartApps catalog refreshed in a hidden background process and cached in app data. search runs entirely in the webview over the in-memory catalog. launch accepts only catalog IDs. no file/web search.

**visual:** UnifrakturCook logo, Nunito Sans interface, Cascadia Code hints. dark #101012 / #f2f0ed / #b0adb5; light #efefee / #242226 / #6e6a73. one search field, seven visible rows, quiet keyboard footer. native acrylic behind real windows, rounded border, 140–180ms reveal and selection transitions; honor reduced motion.

- [x] search coverage: exact/prefix/initials, keyboard layout, subsequence, empty queries, history and unknown matches. multiword order regression observed failing, then fixed.
- [x] search implemented; 1,000 queries measured against the real 167-program catalog, p95 under 1ms for ranking only.
- [x] StartApps catalog, atomic cache, validated launch, single instance, tray and global hotkey with collision fallback.
- [x] themed interface, keyboard navigation, real icons, refresh and error states, persisted recent launches.
- [x] 10 frontend and 2 rust tests pass; typecheck, rust formatting and release/installer builds pass. native acrylic and both themes inspected. real calculator launched by wrong-layout search and Enter; navigation, empty state, theme persistence and unrecognized launch ID rejection checked in the native webview. alt+space was occupied by installed fluent search; ctrl+alt+space verified.

clippy could not run because that rust component is not installed. windows 10, cold boot, installer execution and portable apps without Start Menu registration were not tested.

files: src/search.ts and search.test.ts (ranking); src/main.ts and styles.css (window); src-tauri/src/main.rs (native lifecycle); src-tauri/src/catalog.ps1 (windows discovery and icons); README.md (run and limitations).
